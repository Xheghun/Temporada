## Additional response/race checks

Native 422 classification uses [the loopback failure proxy](../../testing/manual/failure-proxy.mjs), forwarding to the isolated mock on port 3005. Actual backend unknown-document 422 behavior is separately covered by the real HTTP automated suite. Configure with POST `http://127.0.0.1:3006/__test/failure`, JSON `{"status":422}`; route device localhost:3000 to host:3006. `422-failed` and `422-after-manual-retry` preserve one attempt, durable bytes and a localized correction instruction. Explicit replacement creates a new ID and supersedes the failed action.

For the review race, configure proxy `{"status":0,"holdAfterDrop":true}` and backend `dropNextResponse:true`. After the server’s post-commit disconnect, the proxy holds document retries with 503 while allowing assignment refresh. Staff approve that exact submission through the backend development review control. `review-refresh-requested` captures the refresh request before completion; `review-approved-awaiting-replay` subsequently shows Approved **and** the unresolved-delivery explanation. Release with proxy `{"status":0}`. `review-after-replay` and `review-approved-delivered` show delivered intent, the retained newer Approved revision and one server submission. Approval comes from the simulated staff decision, never the upload receipt. Automated TEST-03R covers both Approved and Correction Requested.

The committed proxy was also smoke-tested for 422, 503 and forwarding `/health`; it is a local test tool with no app/runtime imports. Run `node testing/manual/failure-proxy.mjs` only against the isolated mock. It logs no tokens or request bodies.
