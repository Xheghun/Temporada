# Home and versioned terms

SDD-012 uses the existing authenticated runtime and outbox. Enable `worker_home_and_terms` in the HTTPS remote flag response alongside `worker_authentication`; both fail closed. Explicit development assessment mode enables the demo locally. No new API contract or native dependency is introduced.

Home reads assignment, terms, outbox counts and refresh state in one worker-scoped SQLite transaction. The session generation clears old views immediately and rejects late reads. Connectivity is an availability hint, not a delivery guarantee. Pending counts include queued/sending/retry-wait actions; attention counts include permanent failures and an unresolved stale terms confirmation. Refresh requests persist before the engine runs.

The original SDD-012 timeline stated only facts that model supported: authenticated identity, cached assignment, current terms state and required-document catalog count. It did not infer appointments, visa progress, document review or staff approval; SDD-023 below replaces that historical presentation using current document evidence. Documents navigation is available when its `worker_document_corrections` flag is enabled; otherwise it remains explicitly unavailable.

Terms renders the cached localized summary and version. Confirmation captures that displayed version and selection generation, commits through the existing transactional repository, updates local feedback, then signals sync. Duplicate pending confirmations are suppressed. Stale history remains resolved for ordering; newly fetched terms remain unconfirmed until an explicit new action. An old saved notice is never attached to a new version. Permanent failure offers an explicit reconfirm-and-replace button for the displayed version, including the same version. The callback captures the failed predecessor ID; the service revalidates it and the repository atomically supersedes that failure and inserts a new action/intent with a new UUID. Refresh alone never replaces a failed action. Stale history is not superseded.

Spanish is the initial language when no preference exists; existing saved choices are preserved. Home toggles Spanish/English; schema v3 stores the app-wide preference without identity data, tokens or queue deletion. Migration/reopen coverage verifies pending intent survives the upgrade. Layouts scroll and avoid fixed content heights. The complete accessibility audit belongs to its later change.

See [executed verification](https://github.com/Xheghun/Temporada/blob/cd85eadd9c9fc803c70c4938693c9a827621fec2/docs/evidence/home-and-terms.md). Camera, document status/corrections and full integration scenarios remain separate changes.

## Subsequent SDD-022 redesign

SDD-022 replaced the static timeline with a single state-derived next step and catalog rows. Terms needing confirmation precede required corrections, missing required documents and other permanent failures. Pending local work and staff review are reassurance states, not duplicate worker tasks. Unknown/refresh-needed state never implies completion. Home projects document and terms facts from the same atomic cache read and uses the actual selected display name with a neutral greeting. Primary Home/Documents/My Job navigation retains existing route paths and guards; secondary screens use the existing Stack.

My Job presents only cached employer, worksite, order reference and season dates; date-only formatting cannot shift a day across timezones. Terms explicitly describes its content as a summary, preserves displayed-version callbacks and hides stale history behind an accessible disclosure. Existing offline, stale-version and explicit failed-action replacement tests remain intact. Ten new priority/job tests plus existing Home/terms presentation tests, typecheck, lint and architecture checks passed; new native evidence is recorded separately.

## Subsequent SDD-023 Home restoration

This restoration supersedes SDD-022's timeline removal while retaining its next-action hierarchy and visual system. `homeOverview` takes the same atomic worker snapshot and public document presentation facts. Queued/sending/retry-wait terms and documents count as pending; terminal history does not. Missing/failed reads have an unknown count, distinct from loaded zero (even without an assignment). Document progress counts only current required submissions; old reviewed submissions replaced by newer local work do not complete it. Delivery and known review counts are independent, including a staff decision received before replay acknowledgment. Unknown/disabled catalog is unavailable; a loaded empty catalog explicitly has no required documents. Refresh-needed context warns these are saved facts. No new storage, transport, polling or next-action rules.

Home now always shows Online/Offline and the numeric pending count near its top, with concise polite live regions limited to network/count changes. Full cached season dates/reference and current terms version/summary/status stay expanded on Home; My Job and Terms retain detail links. UTC date-only formatting is reused, server summaries remain verbatim in the chosen language, and cached refresh failures do not hide the overview. The expanded progress milestones separate current exact-version terms, required-document delivery and staff review without invented timestamps/appointments. The extra sections intentionally extend the reference Home rather than reverting to the old card layout. The existing next-action priority, route/session guards and queue semantics are unchanged.
