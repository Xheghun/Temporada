# Release plan

1. **Set up store accounts and signing.** Create the app in Google Play Console and App Store Connect using Google Play and Apple Developer accounts. Connect the project to EAS, configure Play App Signing and iOS signing, and keep credentials in EAS and protected CI secrets.
2. **Automate preview builds.** Keep validation on every PR. Extend the existing GitHub Actions and EAS pipeline to build a staging preview after each approved PR merges. Use Play internal testing and TestFlight for signed release candidates.
3. **Test against staging.** Connect the candidates to the staging API and verify offline restart, upload retries, worker switching and permission handling on both platforms. Include an Android 9 phone with 2 GB RAM. Confirm crash reporting and sync metrics capture only non-sensitive data.
4. **Submit and roll out.** After staging QA, build the signed Android bundle and iOS binary with production settings and approve submission. Publish the first version after store review. Stage Android updates at 1%, 5%, 25% and 100%, and use Apple’s seven-day phased release for iOS updates. Review crash rates, failed syncs and queue age before approving wider rollout. Enable new features gradually through remote flags that start off.
5. **Handle regressions.** Pause the rollout and disable the affected feature while preserving pending work. Once EAS Update is configured, use it only for JavaScript changes compatible with the installed runtime. Republish the last working compatible update for an OTA regression. Ship a corrected signed binary for native changes or a broken store build.
