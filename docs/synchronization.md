# Synchronization runtime

SyncEngine receives worker-scoped persistence, transport, session, connectivity, clock, retry policy, feature-gate and event dependencies. It has no React/native/SQLite imports. A process-wide promise guard serializes overlapping runtimes; callers should still own one runtime. Startup recovers interrupted sends once per selected worker. Concurrent triggers coalesce; a worker/session generation change prevents further old-worker dispatch. Late responses update only their captured worker repository and emit worker-tagged events. Consumers must filter events and invalidate views on switch.

`attachSyncTriggers` connects startup, foreground, connectivity restoration, authentication/selection and enqueue subscriptions. `manualRetry()` advances transient deadlines, never permanent failures. The native signal adapter uses AppState/NetInfo; positive connectivity is only a hint. `stop()` removes scheduled wakes; dispose native signals separately. A foreground timer is rebuilt from persisted eligibility and refresh deadlines. OS background delivery is not guaranteed.

The engine processes persisted sequence order, skipping delayed or failed unrelated resources. Terms share a resource; documents share a resource per document type. The earliest unresolved same-resource action blocks successors, even if it is permanently failed. Delivered, stale and explicitly superseded history resolves ordering. A stale v2 never needs supersession before an explicitly confirmed v3.

## Durable outcomes

SyncRepository commits acknowledgment/business state and delivery status together. Original UUID/payload/file remain immutable. 500/network/408/429 use bounded equal jitter, 0.5–1.0 times a 1s exponential delay capped at 60s; attempt count/eligibility survive restart. No transient intent is discarded after an arbitrary attempt limit. 413/422/other permanent 4xx retain bytes and expose codes for future localized remedies. 401/403 requeue the action and invalidate only the captured session generation; authentication must persist invalidation and provide a new authorized generation before resuming. Tokens never enter SQLite.

Explicit failed-document/terms replacement creates new intent and marks the failed predecessor superseded in the same transaction. Active/delivered/stale predecessors are rejected. Document replacement keeps the original server replacement reference, rather than sending an uncommitted local submission ID to the backend. No pending bytes are deleted here.

Delivery and staff review merge independently. A replay receipt may be older than cached staff review: preserve newer status/reason/revision. Equal conflicting revisions abort the transaction; missing/incomparable review revisions preserve known decisions and request refresh. Initial server Pending Review may be recorded without inventing approval. Receipts omit full creation metadata, so acknowledgment requests an independent assignment refresh. Stale terms become historical invalid intent and set persistent terms/assignment refresh flags, without accepting newer terms. Transient refresh failures get independent persisted backoff (migration v2); permanent refresh client errors remain flagged but blocked until explicit refresh/manual resolution; they cannot strand new unrelated deliveries. Replaying a committed v2 after v3 publication acknowledges v2 only.

## Transport and files

Base URL must be supplied; production configuration has no development host default. The transport sends captured Bearer/X-Worker-Id headers, enforces a request timeout, and validates response shapes. Never log tokens or raw responses. The dispatch file resolver requires the worker's private `Paths.document/workers/<workerId>/uploads/<filename>` path, existence, measured bytes below 1,500,000 and matching SHA-256. It snapshots bytes once for hashing/upload. SDK 58 requires awaited File.write and an Expo-compatible Blob for byte-array multipart uploads. Capture still owns compression, durable copying, original cleanup and orphan reconciliation; repository metadata remains a caller attestation.

## Integration boundary

No worker screen or real authentication/session provider is wired by this change. The runtime gate is injected and must fail closed through approved remote configuration in production. Development probes explicitly use `__DEV__`; do not enable the engine with a hard-coded production true. Authentication must wire secure token storage and durable invalidation; UI/capture must publish enqueue and selection signals. Event codes need application-owned translations in the owning UI features. A diagnostic sink is optional and must redact sensitive content before external reporting.

## Reproducing the native probes

Start an isolated backend with `MOCK_PORT=3001 MOCK_ENABLE_CONTROLS=1 MOCK_DATA_DIR=/private/tmp/temporada-native-sync-proof npm run mock:start`, using a fresh dedicated data directory for a fresh v2 run. Start `npm start -- --go --localhost`. Map `adb reverse tcp:8081 tcp:8081` and `adb reverse tcp:3001 tcp:3001`. Open `exp://127.0.0.1:8081/--/dev/sync-check?mode=reset`, then `mode=seed`. Wait for OFFLINE_SEED_PASSED; force-stop `host.exp.exponent`, open `mode=deliver`, and wait for OFFLINE_DELIVERY_PASSED. Cold Expo Go may return to its launcher first; reopen the link if necessary.

Next run `mode=drop-review`, then `mode=stale`, then `mode=files`. The latter checks the real native file resolver; `mode=status` reads worker action IDs/status/attempts without tokens or bytes. These routes are developer-only and use the dedicated proof DB, not worker-cache.sqlite. The seed link tolerates repeated checks before delivery without enqueuing duplicates. Drop/review and stale modes mutate the dedicated mock; use the documented order and do not treat them as production UI. The probe uses a 60-second retry delay to leave time for inspection, and manualRetry to advance eligibility.

Native HTTP may transparently retry a disconnected POST. The drop/review probe explicitly discards a successful returned acknowledgment as well, ensuring the engine's lost-response/review window is tested deterministically. Production transport has no acknowledgment-discard behavior. Corrupt persisted JSON or conflicting equal review revisions pause that worker's loop and report an integrity error for investigation; neither is silently deleted or transmitted.

NetInfo and ExpoBlob require inclusion in a new native binary before release. Do not send this change as JavaScript-only OTA to a binary without those dependencies; release runtime/version approval remains outside this scope.

If a local completion transaction fails after dispatch settles, the engine conditionally releases only that worker/action from sending to queued and stops the pass. Original ID, payload, file and attempt count remain unchanged. If the release write also fails, a targeted in-memory recovery ID is retried before dispatch on the next trigger; process death still falls back to durable startup recovery. Conditional release never rewinds delivered/stale/terminal states. This is separate from network retry classification.
